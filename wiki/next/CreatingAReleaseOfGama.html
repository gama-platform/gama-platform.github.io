Creating a release of GAMA

GAMA can be built locally from Eclipse or Maven. Official release packages are built by the repository's GitHub Actions workflows.

Building a local release from Eclipse​

The GAMA Developer Tools Eclipse plugin provides GAMA > Run GAMA > Build local release... and a matching toolbar button. These are recommended shortcuts; without the plugin, use the command-line Maven build below.

  1. Import the GAMA source projects and keep gama.parent in the Eclipse workspace. Choose a destination outside the source checkout.
  2. Save modified editors when Eclipse prompts. The build uses the saved files, including local changes; it does not fetch or switch branches.
  3. Follow the GAMA Local Release console and Eclipse Progress view. The build can take time and needs disk space for source snapshots, dependencies and product output.
  4. When the build succeeds, the dialog reports the output location and offers Close and Run.

The local build uses a full JDK 25 registered in Eclipse (the Eclipse runtime is used when it is a compatible JDK 25). The tools download Maven 3.9.16 on first use and verify its checksum. Internet access is needed for that download and uncached Maven or p2 dependencies.

The build snapshots the source, then builds gama.annotations, gama.processor and gama.parent in that order. It includes the Maven reactor modules and bundles in features reachable from the saved GUI product definition. Optional integrations are not treated specially: their inclusion depends on the saved reactor and product configuration. Only the current operating system and architecture are built. The result is an unsigned local build, not an official installer.

On macOS, the output is Gama.app. On Windows and Linux, it is a Gama folder containing the launcher and selected JDK. Build and launch logs are included. Existing releases are not overwritten; choose another destination or move the previous output first. macOS security prompts may apply to this unsigned build.

See the local release instructions for the complete setup and behavior.

Building from the command line​

Requirements: a GAMA source checkout, Maven 3.9 and a JDK 25. Set JAVA_HOME to the JDK and check that mvn -version reports Java 25. From the repository root, run:

mvn -f gama.annotations/pom.xml clean install
mvn -f gama.processor/pom.xml clean install
mvn -f gama.parent/pom.xml clean install

The script travis/build.sh runs these same three stages and passes additional arguments to Maven. It disables Maven's build cache for the first two installs so Tycho can discover their local artifacts; the parent build uses the repository's Maven build-cache configuration.

Products are written under gama.product/target/products. The GUI and headless products are materialized for supported platforms, with .zip or .tar.gz archives as appropriate. These command-line archives do not include a JDK and are not signed.

Official releases and pre-releases​

The Create & Publish new GAMA release GitHub Actions workflow is started manually from the repository's Actions tab. It versions and builds the selected commit, packages the supported platforms, and can publish to selected destinations. The build also publishes the p2 update site. Publication destinations are unchecked by default, so starting the workflow does not by itself publish a GitHub release or a third-party package.

InputPurpose
IS_STABLE_RELEASEChoose a stable release or alpha pre-release.
tagVersion and Git tag, in the form YYYY.MM.0.
jdkTemurin JDK version embedded in the packages that include a JDK.
releaseGithub, releaseDocker, releaseMicrosoft, releaseLinuxPpa, releaseNpmGamlSelect publication destinations.
skipTestsSkip release package tests.
USE_BUILD_CACHE, USE_DEPENDENCY_CACHEBuild troubleshooting options.

The GitHub and third-party publication checkboxes control separate destinations. In the current workflow, third-party publishing is downstream of GitHub publication, so leave GitHub publication selected when requesting a third-party release.

The release workflow compiles and signs the GAMA JARs, publishes the p2 update site during the build, then packages Windows, Linux and macOS variants. It runs GAMA and package tests unless skipTests is selected. The packages include variants with and without an embedded JDK. macOS packages are signed and notarized. A stable release is published as the latest release when GitHub publication is selected; an alpha is marked as a pre-release. Third-party publishing can target Microsoft Store, Docker, the Linux PPA and the GAML syntax-highlighting package.

The continuous validation workflows also build and validate changes: pushes (except changes limited to .github/ or travis/) run a build and headless tests unless an open pull request is already validating the branch; pull requests build both the base branch and the proposed changes, test the proposed build and compare SpotBugs reports. The documentation reference is regenerated weekly by a separate workflow.

The release workflow and its reusable build and publication steps are defined in the repository's .github/workflows directory; build and packaging scripts are in travis. The folder name is historical; Travis CI is not used.
