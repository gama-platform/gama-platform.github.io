IScope interface

An IScope (gama.api.runtime.scope.IScope) is the execution context passed through GAML evaluation. It identifies the current object or agent and the agent stack, gives access to local variables and action arguments, tracks control flow, and provides services such as the random generator, clock, topology and GUI. Java implementations of GAML elements receive a scope when they need to evaluate expressions, access arguments or report an error.

ExecutionScope is the main implementation. GraphicsScope implements IGraphicsScope for operations that need a graphics context.

Receiving and using a scope​

GAML operators declare IScope as their first Java parameter. Actions and statements also receive a scope; for example, statement implementations define privateExecuteIn(IScope scope). Pass that scope to the API methods that need it instead of storing it in a field.

To evaluate an expression for a particular object or agent, use evaluate and read the result:

public Object evaluateForAgent(IScope scope, IExpression expression, IAgent agent) {
    return scope.evaluate(expression, agent).getValue();
}

Scope-aware variable access is available through getDirectVarValue(scope, name) and setDirectVarValue(scope, name, value). The agent API also exposes getAttribute(name) and setAttribute(name, value); both are used in the API and GAMA implementation. Choose the method that matches the operation and the surrounding API rather than treating either form as universally required.

An agent exposes its own scope through agent.getScope(). Code running outside a GAML execution can obtain the current runtime scope with GAMA.getRuntimeScope(). The selected context depends on the current simulation and experiment; the method can return null before the platform is loaded. GAMA.run(InScope<T>) executes a function with a temporary copy of the runtime scope and closes that copy automatically:

@Override
public boolean isWorkspace() {
    if (inWorkspace == null) return false;
    return GAMA.run(scope -> Cast.asBool(scope, inWorkspace.value(scope)));
}

This method from ExperimentParameter evaluates a stored expression inside the temporary scope.

Copies and threads​

An ExecutionScope must not be used concurrently by multiple threads. A copied scope can share local-variable frames and the agent stack with its source, depending on how and where it is created. Choose the copy method for the lifetime and concurrency pattern, and clear every copy when it is no longer needed.

MethodShared with the sourceIntended use
copy(name)Shares local variables and the agent stack when called by the thread that owns the source scope; otherwise shares only the root agent and servicesShort-lived work, including work on another thread. Close or clear it when finished.
fork(name)Shares local variables and the agent stack regardless of the calling threadParallel agent execution when the source scope is not concurrently used elsewhere and the parent waits for the forked work. Clear it after the fork and its child tasks finish.
detachedCopy(name)Does not share local variables or the agent stack; retains access to the root agent and servicesLong-lived contexts such as outputs and monitors. Clear it when its owner is disposed.
copyForGraphics(name)Produces an IGraphicsScope with graphics operations; the implementation does not share the source's local-variable frames or agent stackDisplay and layer operations. Clear it when its owner is disposed.

IScope extends Closeable, and close() calls clear(). A short-lived copy can therefore use try-with-resources:

public void executeInCopy(IScope scope, IStatement action, IAgent agent) {
    try (IScope copy = scope.copy("ThreadScope")) {
        copy.execute(action, agent, null);
    }
}

For a longer-lived copy, keep it only for the lifetime of its owner and call clear() or GAMA.releaseScope(copy) when disposing that owner. Do not keep a normal copy(...) in a field: if it shares frames, those frames remain retained until the copy is cleared.

Interruption​

interrupted() is true when the scope has a flow status that interrupts execution: BREAK, RETURN, CONTINUE, DIE or DISPOSE. DISPOSE is also what clear() sets, and isClosed() checks for that status. Long-running Java loops and background work should check interruption where they can stop safely:

public boolean shouldContinue(IAgent agent) {
    IScope scope = agent.getScope();
    return scope != null && !scope.interrupted();
}

Statements that implement GAML control flow set and consume the corresponding flow statuses through methods such as setBreakStatus() and getAndClearReturnStatus().

Errors​

Create a GamaRuntimeException with the current scope when an error should stop the current operation and be reported with its execution context:

private void requireData(IScope scope, IContainer data) {
    if (data == null) {
        throw GamaRuntimeException.error("auto_correlation requires non-nil data", scope);
    }
}

GamaRuntimeException.warning(message, scope) creates a warning. GamaRuntimeException.create(throwable, scope) wraps a Java exception for GAMA's error handling. GAMA.reportError(scope, exception, shouldStopSimulation) reports without unconditionally throwing; use it only when execution can continue safely. GAMA's reporting and stopping behavior also depends on runtime preferences and whether the application is running with a GUI, headless, or server mode.
