Implementing diffusion

GAMA can simulate a variable diffusing through a grid topology or field.

Diffuse statement​

The diffuse statement applies a named variable across a diffusion target. Write the variable name immediately after diffuse; the required on: facet identifies the grid population, field or selected grid agents to use as diffusion sources. The statement can be placed in a behavior such as a reflex in global; it does not have to be declared inside a grid species. Declare the diffused variable on the grid agents when the target is a grid.

The variable name is written after diffuse, not as a var: facet. The statement uses these facets:

  • on (species, field or list of grid agents): the target. A list selects the grid agents whose values contribute as sources; it does not by itself limit the destination cells.
  • matrix (matrix): an explicit diffusion kernel. Its row and column counts must be odd.
  • method (identifier): convolution (default) or dot_product.
  • min (float, default 0.0): the minimum input value considered by the diffusion; it cannot be negative.
  • mask (matrix): values below -1 exclude the corresponding cells as sources; other values leave them eligible.
  • avoid_mask (boolean, default false): when true, contributions directed to masked cells are redistributed among eligible neighboring cells. With the default false, a masked cell can receive a value but does not propagate it onward.
  • propagation (label): diffusion (default) adds contributions that meet at a cell; gradient keeps the maximum contribution and does not reduce the source value.
  • proportion (float), radius (int) and variation (float): parameters used to build the kernel when matrix is omitted. They cannot be combined with matrix.
  • cycle_length (int, default 1): repeats the kernel computation within one simulation step.

The sections below cover matrix-based diffusion and parameter-based diffusion.

This complete model is used in the examples below:

global {
    int size <- 64;
    cells selected_cells;

    // Select the cell at the world location.
    init {
	selected_cells <- location as cells;
    }
    // Set the selected cell's value before each diffusion step.
    reflex new_Value {
	ask(selected_cells){
	    phero <- 1.0;
	}	
    }

    reflex diff {
	// Apply the diffusion kernel to the variable "phero" on the grid "cells".
	diffuse phero on: cells /*HERE WRITE DOWN THE DIFFUSION PROPERTIES*/;			
    }
}

grid cells height: size width: size {
    // "phero" is the variable storing the value of the diffusion
    float phero  <- 0.0;
    // The color of the cell is linked to the value of "phero".
    rgb color <- hsb(phero,1.0,1.0) update: hsb(phero,1.0,1.0);
}

experiment diffusion mode: gui {
    output {
	display a renderer: 3d {
	    // Display the grid with elevation
	    grid cells elevation: phero * 10 triangulation: true;
	}
    }
}

This model sets the selected cell's variable to 1 before each diffusion step, then diffuses values across the grid. The display uses color and elevation to show the result.

Diffusion with matrix​

A first way of specifying the behavior of your diffusion is using diffusion matrix. A diffusion matrix is a 2-dimension matrix [n][m] with float values, where both n and m have to be odd values. The most often, diffusion matrices are square matrices, but you can also declare a rectangular matrix.

Example of matrix:

matrix<float> mat_diff <- matrix([
		[1/9,1/9,1/9],
		[1/9,1/9,1/9],
		[1/9,1/9,1/9]]);

In the diffuse statement, you then have to specify the matrix of diffusion you want in the facet matrix.

diffuse phero on: cells matrix:mat_diff;

An explicit matrix uses diffusion propagation, which combines contributions from multiple source cells. The propagation facet applies to parameter-based diffusion and cannot be combined with matrix; use propagation: gradient there to keep the strongest contribution at each cell.

Diffusion matrix​

A diffusion (the default value of the facet propagation) will spread the values to the neighbors' cells according to the diffusion matrix, and all those values will be added together, as it is the case in the following example:

Away from grid edges (or with a torus), and without masks or a min threshold, the sum after one step is the input sum multiplied by the sum of the matrix weights. If the matrix weights sum to more than 1, values can grow over successive steps; a matrix whose weights sum to 1 preserves the total under these conditions.

Gradient propagation​

For parameter-based diffusion, set propagation: gradient to keep the strongest contribution at each cell instead of adding contributions together. This mode uses proportion, radius and variation to build the propagation kernel; it does not use an explicit matrix.

Because overlapping contributions use the maximum instead of addition, the sum of the kernel weights does not determine the resulting total in gradient propagation.

Compute multiple propagations at the same step​

You can compute several times the propagation you want by using the facet cycle_length. GAMA will compute for you the corresponding new matrix and will apply it.

Writing those two things are exactly equivalent (for diffusion):

matrix<float> mat_diff <- matrix([
		[1/81,2/81,3/81,2/81,1/81],
		[2/81,4/81,6/81,4/81,2/81],
		[3/81,6/81,1/9,6/81,3/81],
		[2/81,4/81,6/81,4/81,2/81],
		[1/81,2/81,3/81,2/81,1/81]]);
reflex diff {
    diffuse phero on: cells matrix:mat_diff;
}

and

matrix<float> mat_diff <- matrix([
		[1/9,1/9,1/9],
		[1/9,1/9,1/9],
		[1/9,1/9,1/9]]);
reflex diff {
    diffuse phero on: cells matrix:mat_diff cycle_length:2;
}

Combining diffusion effects​

When a specific combined distribution is needed, add the weights in one explicit matrix and use it in a single diffuse statement. This makes the kernel's coefficients and orientation clear.

Diffusion with parameters​

Sometimes writing an explicit matrix is not convenient. You can instead configure the generated kernel with proportion, radius, variation and propagation.

The grid neighborhood and selected propagation mode determine how the kernel weights are computed. A radius of R produces a kernel with 2*R+1 rows and columns.

  • With diffusion propagation

For propagation: diffusion, the generated kernel depends on the grid neighborhood. With an eight-neighbor grid, the center weight is 1/9 and each surrounding weight is proportion/9. With a four-neighbor grid, the center and four orthogonal weights are proportion/5; diagonal weights are zero. A radius greater than one builds a wider kernel by repeatedly combining this base kernel. A positive variation is subtracted according to each cell's distance from the center.

  • With gradient propagation

For propagation: gradient, the generated value at distance d from the center is proportion / N^d - d * variation, where N is the grid's neighbor count. Distance uses the maximum coordinate offset for an eight-neighbor grid and the sum of coordinate offsets for a four-neighbor grid. Negative weights are set to zero. Overlapping propagations keep the maximum contribution, and the source value is not reduced.

For example, with radius: 2, proportion: 1, variation: 0 and an eight-neighbor grid:

Do not combine an explicit matrix with proportion, radius, variation or propagation; the validator reports these combinations as errors. Parameter-based diffusion generates an isotropic kernel aligned with the grid neighborhood. cycle_length can also be used with an explicit matrix; it repeats the kernel composition for additional cycles.

Computation methods​

You can compute the output matrix using two computation methods by using the facet method : the dot product and the convolution. Note that the result of those two methods is exactly the same (except if you use the avoid_mask facet, the results can be slightly different between the two computations).

Convolution​

convolution is the default computation method for diffusion. For every output cells, we will multiply the input values and the flipped kernel together, as shown in the following image :

Pseudo-code (k the kernel, x the input matrix, y the output matrix) :

for (i = 0 ; i < y.nbRows ; i++)
  for (j = 0 ; j < y.nbCols ; j++)
    for (m = 0 ; m < k.nbRows ; m++)
      for (n = 0 ; n < k.nbCols ; n++)
        y[i,j] += k[k.nbRows - m - 1, k.nbCols - n - 1] 
            * x[i - k.nbRows/2 + m, j - k.nbCols/2 + n]

Dot Product​

dot_product method will compute the matrix using a simple dot product between the matrix. For every input cells, we multiply the cell by the kernel matrix, as shown in the following image :

Pseudo-code (k the kernel, x the input matrix, y the output matrix) :

for (i = 0 ; i < y.nbRows ; i++)
  for (j = 0 ; j < y.nbCols ; j++)
    for (m = 0 ; m < k.nbRows ; m++)
      for (n = 0 ; n < k.nbCols ; n++)
        y[i - k.nbRows/2 + m, j - k.nbCols/2 + n] += k[m, n] * x[i, j]

Using a mask​

Generalities​

If you want to propagate some values in a heterogeneous grid, you can use some mask to forbid some cells to propagate their values.

You can pass a matrix to the facet mask. All the values smaller than -1 will not propagate, and all the values greater or equal to -1 will propagate.

A simple way to use mask is by loading an image :

When on: receives a list of grid agents, only those cells contribute source values. This is similar to a source mask: it does not restrict which unmasked cells can receive the diffusion.

When your diffusion is combined with a mask, the default behavior is that the non-masked cells will diffuse their values in all existing cells (that means, even the masked cells !). To change this behavior, you can use the facet avoid_mask. In that case, the value which was supposed to be affected to the masked cell will be redistributed to the neighboring non-masked cells.

Tips​

Masks can be used to simulate a lot of environments. Here are some ideas for your models:

Wall blocking the diffusion​

To direct values away from a wall, this example uses a second kernel on wall cells. Its non-zero weights point toward the open side. The weights shown sum to 8/9, so this particular kernel does not conserve the total value; a mass-preserving kernel must sum to 1.

matrix<float> mat_diff <- matrix([
			[1/9,1/9,1/9],
			[1/9,1/9,1/9],
			[1/9,1/9,1/9]]);
								
matrix<float> mat_diff_left_wall <- matrix([
			[0.0,0.0,2/9],
			[0.0,0.0,4/9],
			[0.0,0.0,2/9]]);

reflex diff { 
    diffuse phero on: (cells where(each.grid_x>30)) matrix:mat_diff;
    diffuse phero on: (cells where(each.grid_x=30)) matrix:mat_diff_left_wall;
}

The avoid_mask facet offers another way to handle masked destinations: contributions that would enter masked cells are redistributed among eligible cells, while existing values in masked cells remain unchanged. The convolution and dot_product methods can differ in this redistribution, so choose the method for the behavior required by the model.

Wind pushing the diffusion​

This example combines a uniform diffusion with two wind adjustments. It defines three matrices: the uniform diffusion matrix and one matrix for each wind adjustment. Each wind matrix sums to zero, so adding it changes the distribution of weights without changing their total.

matrix<float> mat_diff <- matrix([
		[1/9,1/9,1/9],
		[1/9,1/9,1/9],
		[1/9,1/9,1/9]]);
								
matrix<float> mat_wind_from_west <- matrix([
		[-1/9,0.0,1/9],
		[-1/9,0.0,1/9],
		[-1/9,0.0,1/9]]);
								
matrix<float> mat_wind_from_north <- matrix([
		[-1/9,-1/9,-1/9],
		[0.0,0.0,0.0],
		[1/9,1/9,1/9]]);

reflex diff { 
    diffuse phero on: cells matrix:mat_diff;
    diffuse phero on: cells matrix:mat_wind_from_north;
    diffuse phero on: (cells where (each.grid_y>=32)) matrix:mat_wind_from_west;
}

Endless world​

Note that when your world is not a torus, it has the same effect as a mask, since all the values outside from the world cannot diffuse some values back :

You can approximate the edge behavior by applying a different diffusion to cells with grid_y = 0:

matrix<float> mat_diff <- matrix([
			[1/9,1/9,1/9],
			[1/9,1/9,1/9],
			[1/9,1/9,1/9]]);
								
matrix<float> mat_diff_upper_edge <- matrix([
			[0.0,0.0,0.0],
			[1/9+7/81,2/9+1/81,1/9+7/81],
			[1/9,1/9,1/9]]);

reflex diff { 
    diffuse phero on: (cells where(each.grid_y>0)) matrix:mat_diff;
    diffuse phero on: (cells where(each.grid_y=0)) matrix:mat_diff_upper_edge;
}

When diffusion takes effect​

GAMA applies registered diffuse operations at the end of the simulation cycle. Regular behaviors can update the source variable during the cycle; the diffusion then uses those values and updates the target before the next cycle. cycle_length repeats the kernel within that end-of-cycle operation.
