Version: 🚧 Alpha 🚧

Changelog

Major changes from 2025-06 to 2026-11​

This major release follows the 2025-06 stable release. For modelers, the main changes are: faster simulations (spatial queries, matrix operations, and data serialization), a new dataframe type for manipulating tabular data directly in GAML, a class system for defining custom data structures, a cleaner GAML syntax, new geospatial capabilities (GeoPackage import/export, raster grid writing), extended chart customization, a solver plugin with shared GAML syntax for constraint programming and mixed-integer linear programming (MILP), ONNX neural network inference, ROS robotics, and gamepad input.

For developers, this release also brings reworked external client libraries (Python and TypeScript/JavaScript) to drive GAMA programmatically from outside the platform, a headless server with command-queue management, and a reworked batch experiment architecture.

Highlights​

  • Faster simulations - spatial queries, matrix/field computations, string operations, and data serialization are all significantly quicker than in 2025-06. Saving and restoring simulation state is now much faster thanks to a new binary format.
  • New dataframe type - manipulate tabular data (pivot, join, group-by, filter) directly in GAML with full static typing. Example models are included in the library.
  • New class system - define your own object types with attributes, methods, inheritance, and composition. Objects can be stored in variables, lists, maps, and passed between agents.
  • Named lambda parameters - name the current element in an iterator and nest operations with a different name at each level.
  • Cleaner GAML syntax - long-deprecated constructs have been removed (with: [a::1], do action:, let/set, list of: T, arrow braces, etc.) and replaced with more readable, unambiguous alternatives.
  • OpenGL4 renderer - an alternative to the existing OpenGL renderer, with equivalent functionality in this release.
  • Updated interface - a refreshed visual style with thinner, more consistent icons and an updated splash screen.
  • Optional GitHub Copilot extension - add a code assistant to the GAML editor by installing the Copilot extension.
  • Reorganized model library - the example model library has been restructured into a clearer hierarchy (Demos, Recipes, Data, Tutorials) so it is easier to find what you are looking for.
  • Two new tutorials - Forager reinforcement learning and SIR sensitivity analysis. Both tutorials include example GAML models in the GAMA model library.
  • New geospatial capabilities - GeoPackage import/export, raster grid writing via GamaGridFile, and improved grid pathfinding.
  • Improved charts - new color palettes, font controls, grid/axis customization, series styling, and a pluggable chart engine for easier extension.
  • New plugins - ONNX neural network inference, a solver plugin with shared GAML syntax for constraint programming and mixed-integer linear programming (MILP), ROS robotics integration, and gamepad input. LLM integration, PMML, Flooding, and graphical modeling plugins are also updated.
  • Reworked external client libraries - the Python library (pip install gama-client) has been completely reworked (v2.0, breaking changes), and the TypeScript/JavaScript library has been fully refactored (v2.1). Both now offer a clean, typed API to control GAMA headless from external programs.
  • More robust headless server - command-queue management, status listening, logging, and a new extension point for custom commands.

Detailed changes​

This release of GAMA contains new features and fixes, including:

  • Performance:

    • Spatial queries (grid and quadtree) are significantly faster, especially in models with many agents (#1265, #1225, #1233, #1247).
    • The Java Vector API speeds up existing element-wise numeric-matrix operations such as +, -, *, /, scalar powers, abs, sin and cos, plus selected field calculations. New matrix-scalar comparisons and matrix-valued ifelse also have vectorized implementations; model expressions need no special vector type or setting (matrix and field optimizations, new matrix operations).
    • String operations (concatenation, matching) in hot loops are faster due to regex caching (#1093).
    • Saving and restoring simulation state is much faster thanks to a new binary serialization format (#1234).
    • Simulation initialization avoids unnecessary memory allocations (#1276, #1125, #1120).
    • Grid pathfinding (BFS) is faster (#1247).
    • Repeated data saving to the same file is faster (file resolution cached) (#1103).

  • Data types & operators:

    • Added matrix operations including shift, scalar comparisons that produce matrices, and matrix-valued ifelse. Grid attributes can be read and assigned as typed spatial matrices with cell[attribute] and cell[attribute] <- matrix; grid collect also preserves spatial structure. These operations support matrix-based grid calculations and replace the older string-based matrix_with(grid, "attribute") and set_values forms; see the migration guide (matrix and grid operations, matrix operation implementations).
    • Named lambda parameters allow nested iterations to refer to the current element at each level, for example agents collect(a: a.my_list sum(b: b.my_value)) (container operator examples).

    • Missing string operators implemented (#760).

See experiment and simulation contexts and user commands in GUI experiments.

Classes and Objects in GAML (new)​

GAMA 2026-11 introduces a full object-oriented class system. You can now define your own data types with attributes, methods, inheritance, and composition, without creating agents. Objects are ordinary GAML values: they can be stored in variables, put in lists or maps, passed as arguments, and returned from actions.

In agent-based modeling, you often need entities that exist purely to represent data (a point, a segment, a configuration, a set of related parameters) or to group functions together. These are not real simulation entities: they do not move, do not interact spatially, and do not need to be scheduled cycle by cycle. Modeling them as agents is possible but wasteful: every agent carries the overhead of spatial indexing, scheduling, and lifecycle management. The new class system lets you represent such entities as lightweight objects: no spatialization by default, no scheduling, no agent overhead. This makes models cleaner (you only create agents for things that truly behave) and faster (less memory, fewer spatial queries, lighter scheduling).

  • class block defines a pure data/logic type (no agent, no population)
  • Attributes declared with the same <type> <name> <- <default> syntax as species variables
  • Constructor call: ClassName(attr1: v1, attr2: v2) - only listed attributes are overridden
  • Methods (actions) with typed parameters and return values
  • Inheritance: a class can extend another class
  • Composition: a class attribute can be of another user-defined class type
  • Objects in collections: list<my_class>, map<string, my_class>, etc.

A class is declared with the class statement:

class point2d {
    float x <- 0.0;
    float y <- 0.0;

    float distance_to(point2d other) {
        return sqrt((x - other.x) ^ 2 + (y - other.y) ^ 2);
    }
}

Instances are created and used like any other value:

global {
    init {
        point2d p1 <- point2d(x: 3.0, y: 4.0);
        point2d p2 <- point2d(x: 6.0);       // y stays 0.0 (default)
        write "distance = " + p1.distance_to(p2);

        list<point2d> pts <- [point2d(x: 1.0, y: 0.0), point2d(x: 4.0, y: 0.0)];
        write "gap = " + pts[0].distance_to(pts[1]);
    }
}

See the full tutorial on Class Definition for a step-by-step guide, and the example models in the library (Classes 01 to 05 + Showcase).

GAMA Server (headless mode)​

The headless server (gama-server) has received significant improvements in this release, making it more reliable and easier to integrate into external workflows:

  • Command-queue management - a new preference (pref_server_command_queue_size, int, default 50) controls the maximum number of pending commands, preventing memory issues when sending many requests rapidly (#1154).
  • Simulation status messages - server clients receive experiment lifecycle updates and a separate run-completion event. Clients can request the current lifecycle state and enable or disable status-bar message forwarding while an experiment is loaded (#1278; command details).
  • New gama.server_command extension point - plugins can register custom commands that are available over the WebSocket protocol (#1129).
  • Desktop server console - the GUI includes a server console for viewing server messages and connected clients, changing the port, and starting, stopping or restarting the server. Its menu also controls startup and exchange logging; the desktop server remains disabled by default.
  • Server regression tests - automated tests cover server command handling, error cases and lifecycle behavior.
  • Crash resilience - ensures an answer is always sent back to the client even when a command crashes, and performs complete cleanup of experiments on error (#1154).
  • Server logging - new preferences (pref_server_log: bool, default false; pref_server_log_directory: string path, default ~/.gama/server-logs) for enabling server-side logging and choosing the log directory (#1154).
  • Various stability fixes (#1068, #1149).

External libraries & tools​

The gama.clients repository provides client libraries to control GAMA headless from external programs - ideal for automation scripts, web dashboards, or integrating GAMA into larger data pipelines. Both libraries communicate over WebSockets with a running gama-server instance and handle the JSON protocol transparently. No GAMA installation is required on the client side.

Python - gama-client (v2.0)​

Install: pip install gama-client

The Python library existed in v1.x but has been completely reworked for this release (v2.0, breaking changes from 1.x):

  • Simplified API - a clean synchronous client (GamaSyncClient) as the default entry point, plus async and awaitable variants for advanced use cases.
  • Removed nest_asyncio dependency - no more event-loop hacks; the library works cleanly in any Python environment.
  • New commands - ask (call an action on a specific agent), validate, describe, download, upload, exit.
  • Seed control - load and reload now accept a seed parameter for reproducible runs.
  • Better error handling - timeouts, connection errors, and runtime GAML errors are properly surfaced without crashing the client.
  • Performance improvements - reduced per-message overhead (shared counter instead of UUID generation), fixed a memory leak in the command loop, and optimized the listening loop.
  • Full test suite - unit tests covering all commands, error cases and edge cases.
from gama_client.sync_client import GamaSyncClient

with GamaSyncClient() as client:
    client.load("my_model.gaml")
    client.play()
    result = client.expression("length(agents)")
    print(result)

TypeScript / JavaScript - gama-client (v2.1)​

Install: npm install gama-client (or use the local build)

The TypeScript library has also been fully refactored (v1 to v2, breaking changes):

  • Clean typed API - all methods return properly typed GamaMessage responses; public types are exposed through the package entry point.
  • Browser support - automatically falls back to the browser's native WebSocket when running in a web page (no Node.js required).
  • Robust experiment lifecycle - stop() properly resolves once the experiment is gone, distinguishes interrupted runs from deliberate pauses, and no longer adopts another session's state.
  • Safer agent references - ask() validates agent reference format and arguments before sending.
  • Full test suite - on par with the Python library, covering all protocol interactions.
import { GamaClient } from "gama-client";

const client = new GamaClient("ws://localhost:6868");
await client.connect();
await client.load("my_model.gaml");
await client.play();
const result = await client.expression("length(agents)");
console.log(result.content);

Reinforcement learning - gama-gymnasium (optimized) and gama-pettingzoo (first release)​

Two companion libraries bridge GAMA with the Python reinforcement learning ecosystem:

  • gama-gymnasium (repository) - exposes a GAMA model as a Gymnasium environment so you can plug any RL algorithm (PPO, SAC, DQN, ...) from Stable-Baselines3 or RLlib directly into your simulation. This release brings performance optimizations and improved stability for long training runs.
  • gama-pettingzoo (repository) - first stable release. Exposes a GAMA model as a PettingZoo multi-agent environment, enabling multi-agent reinforcement learning (MARL) where multiple learners interact with the same GAMA world.

Both libraries communicate over the same WebSocket protocol as gama-server and require no additional GAMA-side setup beyond running a model in server mode.

Changes that can impact models​

The GAML syntax has been modernized in this release. Several long-deprecated constructs are no longer valid and will cause compilation errors, and a number of skills, statements, operators and facets have been renamed or reworked. The most common changes:

  • with: pairs now use parentheses and single colons: with: [size::2] -> with: (size: 2)
  • Parameter-less action calls require an explicit argument list: do my_action; -> do my_action(); (the action: and returns: facets are removed)
  • Arrow expressions no longer use braces: int x -> { cycle * 2 }; -> int x -> cycle * 2;
  • display / experiment names must be valid identifiers, with the label moved to title:
  • let / set, list of: T, arg statements and the value: facet are replaced by plain typed declarations, list<T> and the update: facet
  • save_simulation() is removed; save now uses format: and attributes:
  • The image layer is renamed to picture
  • Skill renames: advanced_driving -> driving, skill_road -> road_skill, skill_road_node -> intersection, communicating -> fipa
  • Operator renames: as_json_string -> to_json, user_input -> user_input_dialog, with_optimizer_type -> with_shortestpath_algorithm
  • Experiment execution controls: simulation pause / resume / paused are deprecated in favor of the experiment agent (experiment.is_paused, simulation.is_on_user_hold)

The complete list of breaking changes, with before/after examples and a migration checklist, is available in the Migration Guide. GAMA also ships a converter that fixes most of these syntax changes automatically: select the models in the navigator and choose "Convert to GAMA 2026 syntax..." in the contextual menu (see the guide for usage and for the command-line form).

Plugins​

Plugins extend GAMA with additional skills, operators, UI views, or example models. See the plugin installation guide for details on how to install and manage them. In this release, four new plugins are introduced (ONNX, Solvers, ROS, Gamepad) and four existing ones have been updated (LLM, Graphical Modeling, PMML, Flooding).

LLM (updated)​

Integrates Large Language Models into GAMA simulations. Agents can send prompts to an LLM, receive structured responses, and use them to drive their behavior. Useful for building social simulations where agents make "intelligent" decisions, or for natural-language interaction with the model.

Changes in this release: Thread-synchronized memory operations (safe multi-agent access to shared LLM context), improved error handling when the LLM service is unavailable, and enhanced 3D visualization in the SE (Societal Evolution) use-case model.

Examples: SE use-case model with 3D display.

Repository

ONNX (new)​

Allows agents to load and run pre-trained neural network models (in ONNX format) directly inside the simulation, without any external service. You define a skill that wraps an ONNX model, then call it from GAML like any other action - pass input tensors, get output tensors back. This is useful for perception tasks (image classification, object detection), prediction, or any ML inference that needs to run at agent speed.

A skill + a set of operators to load models, feed inputs, and read outputs. No Python or external runtime needed - inference happens natively in the JVM via the ONNX Runtime.

Examples: Example models demonstrating model loading and inference within a simulation.

Repository

Solvers (new)​

Provides a shared GAML syntax for constraint programming and Mixed Integer Linear Programming (MILP). Models can formulate and solve either kind of problem from GAML.

Repository

Graphical Modeling (updated)​

Provides a live one-way diagram view of your GAML model in the editor. As you write or modify code, the diagram updates to show the structure: species, their attributes, actions, and how display layers are organized. It is read-only (you cannot edit the model from the diagram), but it helps understand complex models at a glance.

Changes in this release: Editable snapshots (save and restore diagram states), refined palette for better readability, and color-coded display layer bodies to distinguish different views.

Repository

PMML (updated)​

Allows agents to load and apply PMML (Predictive Model Markup Language) models - a standard XML format for machine learning models produced by tools like R, Python (scikit-learn, H2O), or commercial platforms. Agents can make predictions using these models without any external service.

Changes in this release: Syntax reworked to use variables instead of getter operators (the old skill-based approach is removed). Example models updated for GAMA 2026 syntax.

Repository

Flooding (updated)​

Provides a ready-to-use flooding simulation model. Agents represent water cells that spread based on terrain elevation, simulating flood dynamics over a digital elevation model. Useful for disaster planning, hydrology studies, and education.

Changes in this release: Updated for GAMA 2026 syntax compatibility.

Repository (same repo as PMML)

ROS (new)​

Integrates the Robot Operating System (ROS) with GAMA. Agents can communicate with ROS nodes, receive sensor data, and send control commands. This enables co-simulation between GAMA (for high-level planning, multi-agent coordination) and ROS/Gazebo (for low-level robot control and physics).

A skill for ROS communication, operators to publish/subscribe on ROS topics, and example models demonstrating Gazebo/RViz interaction.

Examples: Ground-truth location tracking model, loop model with full path display, Gazebo/RViz interaction examples.

Repository

Gamepad (new)​

Allows you to control GAMA simulations using a game controller (Xbox, PlayStation, or any standard gamepad). Map buttons and axes to simulation actions: pause/resume, step forward/backward, change parameters, trigger agent behaviors. Useful for presentations, interactive demos, or hands-on teaching sessions where a mouse/keyboard is less convenient.

A skill + operators to read gamepad state (buttons, axes, triggers) from within GAML, and to map inputs to simulation actions.

GitHub Copilot (optional)​

An optional GAMA extension adds GitHub Copilot as a code assistant in the GAML editor. It is installed separately and is not part of the default GAMA product. See the extension installation guide.

Model library reorganization​

The GAMA model library has been restructured in this release to provide a clearer, more intuitive hierarchy. The old structure (8 top-level categories: Case Studies, Data, GAML Syntax, Model Exploration, Modeling, Toy Models, Tutorials, Visualization and User Interaction) has been replaced by 4 main categories plus a new recipes/ folder:

CategoryPurposeWhat you will find here
DemosComplete, runnable simulations showcasing GAMA capabilitiesAnt foraging, Boids, Cellular Automata, Comodels (flood+evacuation, plant+weather, urban+traffic), Epidemiology, Games, Learning (KNN, KMeans), Life (Game of Life, Particle Life), Pedestrian, Predator-Prey, Procedural City, Segregation, Soccer, Sugarscape, Traffic, Urban Growth, Waterflow, and more. These are "toy" models meant to be explored and modified.
RecipesFocused examples demonstrating specific GAML features or techniquesOne folder per feature: Define Classes (new), Define Experiments, Define Simulations, Define Species, Define Variables, Loop And Iterations, Scheduler, Spatial Topology, System (shell, clipboard, threads), User Interaction, Visualization, Charts, Benchmarks, Networking, Data Types. Each contains small, self-contained models that isolate one concept.
DataExamples of importing and exporting dataData Importation (CSV, GeoPackage, XML, shapefiles, rasters, images, graphs), Data Exportation (CSV, GeoJSON, GeoTIFF, PNG, SHP, XML, text), Files (zip/unzip), Utils.
TutorialsStep-by-step guided models for learning GAMAIncremental Model (build a model from scratch in 7 steps), Predator Prey Tutorial, Road Traffic (7 progressive models), Luneray flu (6 progressive models), SIR Analysis (sensitivity analysis with LHS, Morris, Sobol, stochastic methods).
recipes/ (new top-level)Short examples to get startedA lighter-weight set of examples for the most common tasks: Define Classes, Define Experiments, Define Multiple Simulations, Define Species. Designed as a first entry point for new users.

The old structure mixed concerns: "Toy Models" contained both simple demos and complex comodels, "GAML Syntax" was a catch-all for language features, and "Visualization and User Interaction" mixed display examples with interaction patterns. The new structure separates by intent: do you want to see a complete simulation (Demos), learn one specific feature (Recipes), work with data (Data), or follow a guided tutorial (Tutorials)?

Many existing models were simply moved to their new location and updated for the new syntax - they are not new content. The list below contains only the truly new models (66 files) that did not exist in 2025-06, with direct links to the source at commit 260f9b0:
