Manipulate OSM Datas

This tutorial shows how to prepare OpenStreetMap (OSM) data in QGIS and load the resulting vector layers into GAMA. It prepares separate shapefiles for buildings, parks and roads, then adds attributes used by the model example.

GAMA can also read and import OpenStreetMap data natively and create agents from them, without any external tool: see Data > OpenStreetMap Data > models > OSM File Import.gaml, available with the OpenStreetMap plugin. The tutorial below goes the other way round: it prepares the data outside GAMA and exports them to shapefiles, which GAMA reads directly.

Choose a small area on openstreetmap.org and use its Export panel to download the selected bounding box as an .osm file. The website export has size and complexity limits; for larger areas, use an extract or query service such as Geofabrik Downloads or Overpass.

OpenStreetMap data are licensed under the Open Database License (ODbL). If you share a map, dataset or derived work, follow the attribution and share-alike requirements that apply to that use.

The downloaded file can be filtered and its attributes prepared in QGIS before loading the resulting layers into GAMA.

Open QGIS Desktop and install the QuickOSM plugin from Plugins > Manage and Install Plugins…: search for QuickOSM, select it and choose Install Plugin. The QuickOSM user guide describes the plugin's current query interface.

In QuickOSM, choose OSM File, select a local .osm or .pbf file, then choose the geometry types and output destination. QuickOSM can expose point, line, multiline and multipolygon layers; the available features depend on the source file. See the QuickOSM Processing guide for additional import and processing options.

Inspect the resulting layers and their attribute tables before preparing model inputs. This example uses building polygons, park polygons and roads. QGIS may expose the OSM data in separate point, line and polygon layers; use the layer whose geometry and tags match the features you need.

For this example, prepare separate building, park and road layers for the GAMA species. In the polygon layer's attribute table, select buildings with the expression "building" IS NOT NULL; it keeps any feature that has a building value. OSM uses different values for building types, so keep the original attribute values. See the QGIS expression guide for expression syntax.

The selected building features are highlighted on the map.

Save the selected features as a new vector layer in the project's includes folder; this example names it OSM_For_GAMA_Buildings. For a vector layer, use Export > Save Selected Features As… from the layer's context menu, choose ESRI Shapefile as the format, and set the output file. The QGIS guide to creating layers describes these export options. Check the resulting layer before using it in GAMA.

Add the attrForGam field to the buildings layer so the GAMA model can assign colours. Open its attribute table, enable editing, and open the Field Calculator. QGIS documents the Field Calculator and edit workflow.

Create a new text field named attrForGam. Select a string field type so it can store the colour labels used by the example model.

For this example, the field values are randomly assigned red or blue. In the Field Calculator's Function Editor, add a custom function and enter:

from qgis.core import *
from qgis.gui import *
import random

@qgsfunction(args='auto', group='Custom')
def myFun(value1, feature, parent):
    return random.choice(["blue","red"])

Save the function, then use it in the expression editor.

Enter this expression to populate the field: myFun('attrForGam')

Apply the expression, then check the attribute table to confirm the new field contains red or blue values.

An OSM file may not contain every attribute needed by a model. This example creates a Height field with values from 20 to 50 metres. Repeat the field-calculator steps with this custom function:

from qgis.core import *
from qgis.gui import *
import random

@qgsfunction(args='auto', group='Custom')
def myFunHeight(value1, feature, parent):
    return random.randint(20, 50)

Enter myFunHeight('Height') in the expression editor, apply it, and check that the field has been populated.

Save the building layer edits before leaving edit mode. QGIS keeps edits in memory until they are saved; see the attribute table guide for the edit and save controls. The building layer is ready. To prepare parks, select the relevant features from the original polygon layer. Use QGIS's spatial selection tool and hold Shift while selecting multiple park polygons. Check the selection on the map before exporting it.

Export the selected parks as a new shapefile named OSM_For_GAMA_Parks in the project's includes folder.

For roads, use the line layer from the OSM data. If some roads should be excluded, select them and remove them while editing the layer; save the edits before exporting the complete road layer as OSM_For_GAMA_Roads.

Save the roads shapefile in the project's includes folder. Keep all files belonging to each shapefile together when moving or sharing the project.

These steps can be repeated as many times as needed, according to the level of detail required by the model. OSM provides a large number of land use types, which cannot all be covered here; the procedure is always the one described above.

You can now load the three shapefiles from the project's includes folder in GAMA. Keep all component files that belong to each shapefile together when moving or sharing the project. Export the layers in the same coordinate reference system and keep the .prj files with them. The model reads the CRS from the buildings shapefile and applies it to the other two layers.

model OSMtutorial

global {
    // Global variables related to the Management units

    string dataCRS <- crs(file("../includes/OSM_For_GAMA_Buildings.shp"));
    file shapeFile1 <- shape_file("../includes/OSM_For_GAMA_Buildings.shp", dataCRS);
    file shapeFile2 <- shape_file("../includes/OSM_For_GAMA_Parks.shp", dataCRS);
    file shapeFile3 <- shape_file("../includes/OSM_For_GAMA_Roads.shp", dataCRS);

    // Focus the environment on the buildings in the selected area.
    geometry shape <- envelope(shapeFile1);

    init {
    //Creation of Buildings agents from the shapefile (and reading some of the shapefile attributes)
    create Buildings from: shapeFile1
        with: (elementHeight: int(read('Height')), elementColor: string(read('attrForGam')));

    create Parks from: shapeFile2;

    create Roads from: shapeFile3 where (each != nil);
    }
}

species Buildings{
    int elementHeight;
    string elementColor;

    aspect basic{
    draw shape color: (elementColor = "blue") ? #blue : ( (elementColor = "red") ? #red : #yellow) depth: elementHeight;
    }
}

species Parks {

	aspect basic {
		draw shape color: #green;
	}
}

species Roads {

	aspect basic {
		draw shape color: #grey width: 3#meter;
	}
}

experiment main mode: gui {
    output {
    display HowToUseOpenStreetMap renderer:3d {
       species Buildings aspect: basic;
       species Parks aspect: basic;
       species Roads aspect: basic;
    }
    }
}

Here is the result: buildings are coloured according to attrForGam and extruded according to Height, while parks and roads are drawn as separate species.
